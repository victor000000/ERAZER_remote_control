# 1.0.1: scheduled task preservation

Current version before this patch: 1.0.0. Target module version: 1.0.1.
No existing next-version plan or version sequence beyond 1.0.0 was found.

## Design and critical review

Task state must positively establish that an operation is safe. The old generic
registration check rejected Running/Queued but allowed Unknown or unrecognized
states with Force. The start helper likewise accepted unknown states if Enabled.
Registration now accepts only Present/Missing query results; an existing task
must be Ready or Disabled to be considered idle. Starting requires Ready and
Enabled. Tests use synthetic states and mocks, with no real task or HTTP calls.

The documented S001 preservation boundary was not enforced by generic task
registration. Even an idle SQX-Task1-Headless could be replaced with Force.
Generic registration now refuses actual creation/replacement of that reserved
name, case-insensitively and after trimming task-path separators. WhatIf remains
a nonmutating preview. Dedicated preserving operations remain owned by the S001
runbook. Other task names retain the existing explicit-Force replacement flow.

Assumptions: the reserved S001 task name remains SQX-Task1-Headless, and Windows
scheduler states Ready/Disabled establish idle at inspection time. Renamed
preserving tasks need an explicit follow-up policy. State can change between
inspection and registration; this patch does not claim atomic cross-process
locking. It does not establish live task/session behavior or deploy anything.

## CI reconciliation

The live working checkout still had the old matrix expression in step shell,
while the previously verified publication checkout already used separate fixed
shell steps. Reuse that verified workflow, including immutable Action pins and
Python syntax compilation, so the next source release retains the CI fixes.
No deployment step is added.

## Validation

Verified locally on 2026-11-07: both Windows PowerShell 5.1.26100.9711 and
PowerShell 7.6.9 passed 265/265 tests, parsed 238 files and safety-linted 42
maintained files with no diagnostics. Module coverage was 93.94% and 93.76%
respectively (90% required). All five Python helpers compiled without execution.
The final 265-test matrix passed in a fresh clone of the publication branch
using the existing pinned dependency cache. The extra regressions check that an
exactly matching Ready task can still start and that case/root-path variants of
the preserving task name remain protected. Network dependency installation and
new hosted-CI results are recorded separately in ignored release artifacts.
See ignored out/release-1.0.1/ for exact local results. Added regressions cover
unknown/empty/unrecognized run states, unrecognized query results, and both
replacement and recreation of the reserved task. Live SQX, network, trading and
protected data are outside this release's test scope.

The local checkout already includes unrelated operational/documentation edits;
this release preserves them. Source validation does not publish or deploy them.
